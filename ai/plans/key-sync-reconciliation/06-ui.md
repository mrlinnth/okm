# Phase 6: Frontend UI

Depends on: Phases 1–4 (all `/servers/*` sync/migrate endpoints working).
Reuses the Alpine.js/htmx layout wiring and daisyUI modal conventions
established in Classic key manager and Saved servers registry.

### Task [6.1]: Unresolved-diff indicator and Sync now modal [DONE]

#### Subtasks

- [ ] On `app/Views/servers/index.blade.php` (from Saved servers registry),
      add a "Sync now" action to each server card's action row.
- [ ] On page load (or card render), best-effort call `GET`/`POST
  /servers/{id}/sync` per active server to compute the amber
      unresolved-diff dot — if the check fails or times out for a server,
      simply omit the dot for that card rather than blocking the page.
- [ ] Sync now → daisyUI modal with two sections matching
      `ai/prototype/blueprint.md`'s "Saved Servers" screen: "Found on
      server, not in ledger" (list + optional textarea for pasted
      `key_name: date` lines + a resolve action calling
      `POST /servers/{id}/sync/import`) and "In ledger, missing on server"
      (per-item "Remove record" button calling
      `POST /servers/{id}/sync/remove`). Resolved rows flip their button
      label and turn green, matching the prototype. Show "Everything's in
      sync" when both sections are empty.

#### Key Files

- `app/Views/servers/index.blade.php`

#### Verification

Manually add a server, create a key directly via the Outline API (bypassing
the app) to simulate drift, confirm the amber dot appears and Sync now
correctly shows it under "Found on server"; resolve it and confirm the dot
clears on the next check.
